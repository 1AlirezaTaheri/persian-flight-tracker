# رادار پرواز فارسی

ردیابی موقعیت هواپیماها با پایتون، فلسک، لیفلت و نقشهٔ اُپن‌استریت‌مپ؛ بدون حساب کاربری، کلید API یا پایگاه داده.

## ساختار فایل‌ها

```text
persian-flight-tracker/
├── requirements.txt
├── app.py
├── templates/
│   └── index.html
├── static/
│   ├── style.css
│   └── app.js
└── README.md
```

## نصب و اجرا در اوبونتو

اوبونتو ۲۲٫۰۴ یا جدیدتر با پایتون ۳٫۱۰ یا جدیدتر و دسترسی اینترنت نیاز است.
فایل‌ها را با ساختار بالا در پوشهٔ `~/persian-flight-tracker` کپی کنید. سپس:

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip
cd ~/persian-flight-tracker
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python app.py
```

سرور روی همهٔ رابط‌های شبکه و پورت ۵۰۰۰ اجرا می‌شود. ترمینال را باز نگه دارید.
در مرورگر خود اوبونتو، نشانی `http://127.0.0.1:5000` را باز کنید. برای توقف، `Ctrl+C` بزنید.

در ترمینال دیگری برای بازکردن مرورگر اوبونتو:

```bash
xdg-open http://127.0.0.1:5000
```

## بازکردن از ویندوز میزبان یا دستگاه دیگر

آی‌پی ماشین مجازی را در اوبونتو پیدا کنید:

```bash
hostname -I
ip -4 route get 1.1.1.1
```

در خروجی دستور دوم، نشانی بعد از `src` را بردارید. مثلاً اگر `192.168.80.128` بود،
در مرورگر ویندوز `http://192.168.80.128:5000` را باز کنید؛ آی‌پی نمونه را با آی‌پی واقعی عوض کنید.
`0.0.0.0` نشانی مرورگر نیست؛ فقط نشانی اتصال سرور است.

در VMware کارت شبکهٔ ماشین باید وصل باشد. حالت NAT معمولاً دسترسی میزبان به مهمان را فراهم می‌کند؛
حالت Bridged ماشین را در شبکهٔ محلی قرار می‌دهد. حالت Host-only به‌تنهایی اینترنت موردنیاز سرویس را فراهم نمی‌کند.
بدون نیاز، تنظیمات شبکهٔ فعلی را تغییر ندهید.

اگر فایروال اوبونتو فعال است:

```bash
sudo ufw status
sudo ufw allow 5000/tcp
```

برای برداشتن این قانون پس از اتمام استفاده:

```bash
sudo ufw delete allow 5000/tcp
```

برای عیب‌یابی اتصال، در اوبونتو اجرا کنید:

```bash
curl -i http://127.0.0.1:5000/api/aircraft
ss -ltnp | grep ':5000'
```

## کش، محدودیت سرویس و معنی داده‌ها

- یک ترد پس‌زمینه با شروع برنامه فعال می‌شود. در حالت عادی، شروع درخواست‌ها حدوداً هر ۱۲ ثانیه است؛ همهٔ کاربران همان کش مشترک را می‌خوانند.
- مسیر `GET /api/aircraft` هیچ درخواست مستقیمی به اُپن‌اسکای نمی‌فرستد. خروجی آن شامل `aircraft`، زمان موفقیت دریافت `updated_at`، زمان دادهٔ منبع `source_time`، وضعیت `stale`، پیام `error` و `next_fetch_at` است. زمان‌ها ثانیهٔ یونیکس هستند.
- هر هواپیما دارای `icao24`، `callsign`، `origin_country`، `longitude`، `latitude`، `altitude`، `velocity`، `true_track` و `on_ground` است. ارتفاع از `baro_altitude` و برحسب متر است؛ سرعت API برحسب متر بر ثانیه است و در رابط در ۳٫۶ ضرب می‌شود.
- موقعیت‌های ناموجود یا نامعتبر حذف می‌شوند؛ ارتفاع، سرعت و جهت ناموجود به‌صورت «نامشخص» نمایش داده می‌شوند. صفر با دادهٔ ناموجود اشتباه گرفته نمی‌شود.
- کشور، کشور ثبت کد هواپیما است، نه لزوماً مبدأ پرواز. شناسهٔ جستجو همان کال‌ساین دریافتی است و الزاماً شمارهٔ تجاری روی بلیت نیست.
- نقشه ابتدا روی ایران با مختصات `32.4, 53.7` و بزرگ‌نمایی `5` قرار می‌گیرد؛ دادهٔ دریافتی جهانی است. جستجو و فیلتر روی دادهٔ کش‌شده انجام می‌شوند؛ برای دیدن نتیجهٔ خارج از نمای فعلی، نقشه را جابه‌جا کنید.
- هنگام خطای شبکه، پاسخ نامعتبر یا محدودیت سرویس، آخرین دادهٔ موفق نگه داشته می‌شود و «خطا در دریافت داده» نشان داده می‌شود. پیش از اولین دریافت موفق، فهرست خالی است؛ دادهٔ ساختگی نمایش داده نمی‌شود.
- طبق مستندات فعلی اُپن‌اسکای، دسترسی ناشناس ۴۰۰ اعتبار در روز دارد و درخواست جهانی ۴ اعتبار مصرف می‌کند؛ بنابراین تقریباً ۱۰۰ درخواست، یعنی حدود ۲۰ دقیقه با فاصلهٔ ۱۲ ثانیه، سهمیه را مصرف می‌کند. مصرف دیگر برنامه‌های همان آی‌پی نیز حساب می‌شود. استفادهٔ رایگان و ناشناس با این فاصله نمی‌تواند ۲۴ساعته تضمین شود.
- در پاسخ `429` یا رسیدن اعتبار باقی‌مانده به صفر، برنامه هدرهای `X-Rate-Limit-Retry-After-Seconds` و `Retry-After` را رعایت می‌کند؛ بدون هدر زمان انتظار، محافظه‌کارانه ۲۴ ساعت صبر می‌کند. خطاهای معمول با فاصلهٔ افزایشی تا ۵ دقیقه تکرار می‌شوند. برای دورزدن سهمیه، برنامه را مکرراً راه‌اندازی نکنید.
- زمان رابط به وقت تهران است. دادهٔ قدیمی‌تر از ۴۵ ثانیه با هشدار نشان داده می‌شود. تعداد صفر در ایران الزاماً خطای نرم‌افزار نیست؛ پوشش گیرنده‌ها محدود است.
- فونت وزیرمتن و لیفلت از CDN و کاشی‌ها از اُپن‌استریت‌مپ بارگذاری می‌شوند؛ اینترنت برای سرور و مرورگر لازم است. نام مکان‌های روی کاشی‌های نقشه را ارائه‌دهنده تعیین می‌کند و همهٔ آن‌ها الزاماً فارسی نیستند.

مستندات منبع داده: https://openskynetwork.github.io/opensky-api/rest.html

## اجرای دائمی‌تر

دستور `python app.py` برای آزمایش و استفادهٔ محلی است. برای استقرار روی شبکهٔ مورداعتماد می‌توانید از گانیکورن استفاده کنید:

```bash
cd ~/persian-flight-tracker
source .venv/bin/activate
python -m pip install gunicorn
gunicorn --workers 1 --threads 4 --bind 0.0.0.0:5000 'app:create_app()'
```

حتماً فقط **یک پردازهٔ worker** اجرا کنید؛ کش حافظه‌ای میان چند پردازه مشترک نیست و چند پردازه سهمیه را چندبار مصرف می‌کند.
از `--preload`، دیباگر و بارگذار مجدد استفاده نکنید. این برنامه ورود کاربری ندارد؛ برای انتشار عمومی، پراکسی معکوس و HTTPS را جداگانه تنظیم کنید.
